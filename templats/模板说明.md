# 物模型模板说明

模板以 JSON 文件形式存放在 `templats/` 目录，文件名约定 `{Code}.json`。启动时全量扫描加载，按 `code` 唯一索引。

## 通用约定

- **编号（number）**：属性/服务/告警的编号从 0 开始自动生成（0,1,2...），不可修改；删除后自动重排保持连续。
- **类型（type）**：属性分为 `status`（状态类型）与 `number`（数据类型）；服务分为 `status`（状态类型）与 `number`（数值类型）。
- **默认值（default）**：可为 `null`，表示不设置默认值。
- **单位（unit）**：选填。
- **设备实例 ID**：新建设备时自动生成，格式 `Device-001`、`Device-002` ...（取已有最大序号 +1），不可修改。

            "default": null,    # 属性默认值，可为 null 表示不设置

                {
                    "enum": 0,        # 状态值，不可修改
                    "key":"offline",  # 状态标签
                    "name":"离线",     # 状态名称
                    "value": 0,       # 工程值（实际采集值，可能在实际设备是其他数值，需要配置端进行值对应；属性允许留空存 null）
                },
                {
                    "enum": 1,
                    "key":"online",
                    "name":"在线",
                    "value": 1,
                },
                {
                    "enum": -999,
                    "key":"unknown",
                    "name":"未知",      # 未知状态：属性配置时自动添加，不需要手动
                    "value": null,      # 工程值留空
                }
            ],
            # 属性绑定(字典), 实例化设备时候, 按网关/通道/设备/属性 四级定位实际点位,支持简单的聚合方法，ept,sum,avg,min,max,and,or,not（绑定不是必须的，可留空）

            # min: 对多个属性值取最小值
            # max: 对多个属性值取最大值
            # and: 对多个属性值进行逻辑与操作
            # or: 对多个属性值进行逻辑或操作

                "method": "ept", # 默认 ept 直接绑定，不聚合

                    "propertyId": ""

            "name": "工作状态",
            "default": null,
            "unit":"",
            "type":"status",
            "description": [
                {
                    "enum": 0,
                    "key":"halt",
                    "name":"停机",
                    "value": 0,
                },
                {
                    "enum": 1,
                    "key":"standby",
                    "name":"待机",
                    "value": 1,
                }
            ],
            "binding": [
                "method": "ept",
                {
                    "gatewayId": "",
                    "channelId": -1,
                    "deviceId": -1,
                    "propertyId": ""
                }
            ]
        },
        {
            "number":2, # 属性编号，自动生成
            "key": "voltage",    #  标识符
            "name": "电压",
            "default": null,       # 默认值可为 null
            "unit":"V",          # 属性单位，选填
            "type":"number",    # 数据类型：可聚合，无状态值描述
            "description": [

            "binding": [

            "number":5,
            "key": "energy",
            "name": "电量",
            "default": null,
            "unit":"kWh",
            "type":"number",
            "description": [

            "binding": [
                "method": "sum", # 加法聚合， 对多个属性值进行求和， 仅对数据类型属性进行聚合
                {
                    "gatewayId": "",
                    "channelId": -1,
                    "deviceId": -1,
                    "propertyId": ""
                },
                {
                    "gatewayId": "",
                    "channelId": -1,
                    "deviceId": -1,
                    "propertyId": ""
                }
            ]
        },
    ],
    "methods":[
        {
            "number":0, # 服务编号，从 0 开始自动生成，不可修改
            "key": "onoff", # 标识符（服务英文名称）
            "name": "开关机", # 服务名称

            #有效性检查：数值类型时可配置最小值/最大值；状态类型不需要
            "validation": {
                "min": 0,

                    "key":"off",    # 状态标签

                "max": 125,

            "descriptions": [
            ],
            "binding": {
                "gatewayId": "",
                "channelId": -1,
                "deviceId": -1,
                "propertyId": ""
            }
        }

        {
            "number":0, # 事件编号，从 0 开始自动生成，不可修改
            "name": "通讯故障", # 事件名称
            "key": "communicationFault", # 事件英文名称
            "description": "设备通讯故障事件", # 事件描述
            "level": 0, # 0-提示性告警， 1-一般性告警， 2-严重性告警， 3-紧急故障
            "type": "equal", # 触发类型,equal-等值触发， upper-上阈值触发， lower-下阈值触发
            "threshold": 0, # 触发阈值， 当事件值等于阈值时， 触发事件
            "time": 0 # 触发时间， 单位毫秒， 当事件值在阈值范围内持续时间超过该值时， 触发事件, 0表示立即触发
        }
    ]
}

## 设备实例化约定

模板文件只定义属性、服务和告警的语义。实际点位的 `gatewayId`/`channelId`/`deviceId`/`propertyId` 四级定位、聚合来源与状态值工程值映射属于设备实例配置；平台在创建设备时保存模板快照和实际绑定到 SQLite 数据库。因此同一个模板可安全实例化为多台设备，彼此的点位映射不会覆盖。

设备实例 ID 由平台自动生成（`Device-001`、`Device-002` ...），不可修改。

设备实例中的属性绑定使用对象结构：

```json
{
    "method": "ept",
    "sources": [
        { "gatewayId": "GW1", "channelId": 0, "deviceId": 0, "propertyId": "voltage" }
    ]
}
```

`status` 属性只支持 `ept` 直接绑定；`number` 属性可使用 `sum`、`avg`、`min`、`max`、`and`、`or`、`not` 等聚合方法。服务绑定为单一对象（四级定位一个下发点位）。

设备实例中的告警配置使用 `events` 对象结构：`rule` 为模板告警规则快照（纯定义），`binding` 为检测点位关联列表——每个检测点位匹配一条或多条告警规则：

```json
{
    "rule": [
        { "key": "overVoltage", "name": "过压告警", "level": 2, "type": "upper", "threshold": 250, "time": 3000 }
    ],
    "binding": [
        {
            "point": { "gatewayId": "GW1", "channelId": 0, "deviceId": 0, "propertyId": "voltage" },
            "method": "or",
            "rules": ["overVoltage", "underVoltage"]
        }
    ]
}
```

- 关联一条规则时 `method` 为 `ept`（直接判定）；
- 关联多条规则时 `method` 为 `and`（所有规则都判定成立）或 `or`（任意一条判定成立，默认）；
- 各规则按自身的触发类型、阈值与持续时间判定，检测点位不可重复关联同一条规则。

## 历史版本说明

- 旧版属性/服务类型 `enum` 已统一更名为 `status`（状态值描述数据结构不变），`templats/` 目录中的模板文件已同步更新。
- 旧版未知状态 `enum: -1` 已统一改为 `enum: -999`。
- 当前代码**不做旧版兼容**：含 `enum` 类型的模板保存时会被校验拒绝；数据库为全新建立，不含历史快照。
